# 決定ログ

新しいものを上に足す。1項目は数行。書式は `_templates/decision.md`。

## 2026-11-27 カードのテストファイルを5つにまとめる
- `src/core/cards/` のテスト26個を、種類ごとの5ファイルにまとめた。元のファイルごとに `describe('元のファイル名')` で包み、補助関数は describe の中に閉じ込めた（名前がぶつからない）。中身・件数は変えていない。
- 理由：ファイル数が多くて見通しが悪いため（ユーザーの希望）。新しいテストもファイルを増やさず、合う describe に足す。
- 使い捨ての `__scratch3.test.ts`・`__scratch_lines.test.ts` はまとめずに残した（その後、ユーザーの希望で削除）。

## 2026-11-27 構文解析 grammar.ts を textParser の受け皿として入れる／エンジンに処理を足す
- grammar.ts は textParser で読めなかった行だけを読む（`parseAbilityText` の最後）。読めたら textParser が入れた手動処理を取り消して置き換える。読める範囲を広げてから textParser を削っていく。
- 例文の21行のために足したエンジンの処理：次の自分のターンの終わりまで続く効果（`turnStatic.untilNextTurnEnd`）、選ぶだけの効果（`choose`）、そのカードの持ち主の山札から（`deckTopTo.who: 'chosenOwner'`）、表向きにしてシールドの上に置く（`shieldTop`）、出る時の置換（静的 `enterInstead`）、表向きのシールドを墓地に置く置換（`faceUpShieldToGrave`）、CRY-S-MAX進化（`avertCost`・`avertLossShield`）、革命チェンジで出た条件（`enteredByRevolution`）、能力名ごとの1ターン1回（`markUsed`・`usedThisTurn`）、マナをタップせずに使った条件（`playedFreeThisTurn`、呪文は `castSpell.paid` で数える）、出たターン・「出た時」能力を持つ・表向きのフィルター、山札を見て選ぶ時のコストの合計の上限（`pickMaxTotalCost`）、唱えている呪文を裏向きでシールドに加える（`selfAction: 'shield'`）。
- 簡単にしたところ：シールドの上に置く時、どのシールドの上かは重なりの少ないものを自動で選ぶ。CRY-S-MAX進化で破壊する表向きのカードはコストの小さいものから自動で選ぶ（負ける時の置換と同じ）。負ける時はシールドを置けるならシールドを使う。

## 2026-11-27 能力テキストの読み取りを「語の組み立て」方式に作り替える
- 字句解析（lexer.ts）→ 構文解析 → 効果定義への変換、の3段にする。最終的に textParser.ts を置き換える（並べて使う案・比べるだけの案は採らなかった）。
- 理由：正規表現を文の形ごとに足す方式は3200行を超え、新しい言い回しのたびに増える。語と辞書に分ければ、言い回しの追加が表への1行で済む。
- 1段目は字句解析だけ作った。辞書にないカタカナ語は種族名の候補として残し、辞書には入れない。

## 2026-11-27 Obsidian の Vault を Claude の外部記憶にする
- `vault/` を Obsidian の Vault にし、`CLAUDE.md` から入口を指す。巨大ファイルは `vault/codemap/` の行番号で部分読みする。
- 理由：engine.ts・textParser.ts だけで約40万文字あり、毎回読むとコンテキストを使い切るため。
- 地図は `npm run codemap` で自動生成（手で書かない）。手書きのノートには「なぜ」「落とし穴」「やりかけ」だけを書く。

## （以前から）読めない能力は手動処理にする
- 読み取れない能力は `type: 'manual'` で残し、エンジンは自動処理しない。プレイヤーが右クリックメニューで手動操作し、ログに残る。
- 理由：誤って自動処理するより、手で処理する方が安全。

## （以前から）エンジンは UI に依存しない純粋な TypeScript
- UI とは `Action` と `GameState` だけでやり取りし、状態は JSON で保存・復元できる。乱数もシードを状態に持つ。
- 理由：中断保存・オンライン同期・テスト・再現のため。
