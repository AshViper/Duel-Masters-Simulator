# Card Duel Simulator

デッキ構築と対戦ができる、ブラウザで動く個人用カードゲームシミュレーター（仕様書 v1.0 の基本版）。

## 起動

```
npm install
npm run dev        # http://localhost:5173
npm test           # ユニットテスト（Vitest）
npm run build      # 型チェック + ビルド
npm run test:e2e   # UIテスト（Playwright。初回は npx playwright install chromium）
```

### GitHub Pages で公開する

`main` に push すると `.github/workflows/pages.yml` がテスト・ビルドして GitHub Pages に公開します（公開先: https://ashviper.github.io/Duel-Masters-Simulator/ ）。
初回だけ、リポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」にしてください。

Pages 版はサーバーを使わずに、すべての機能（公式カード検索を含む）が動きます。

#### GitHub Pages で公式カード検索を使う（ブックマークレット）

公式サイトはほかのサイトからの読み取り（CORS）を許可していないため、Pages 版のアプリからは直接取得できません。そこで、**あなたが開いた公式カード検索のタブに取得を代わりにしてもらいます**（サーバーや第三者のサービスは使いません。仕組みは `src/ui/officialBridge.ts`）。

1. Pages 版の「公式カード検索」画面にある「DMシミュへ接続」ボタンを、ブラウザのブックマークバーへドラッグして登録する。
2. [公式カード検索](https://dm.takaratomy.co.jp/card/) で欲しいカードを検索し（またはカードの詳細ページを開き）、登録したブックマークを押す。
3. Pages 版が開き（ポップアップの許可を求められたら許可）、**そのページに出ているカード（最大100枚）が自動で保存されます**。保存済みのカードは取りに行きません。
4. つながっている間は、Pages 版の中でも公式カード検索・保存・デッキ構築の「公式から探す」・デッキ文字列の読み込みがローカル版と同じように使えます。

- 公式サイトのタブは開いたままにしてください（タイトルに「[接続中]」と付きます）。閉じたり別のページへ移ったりしたら、もう一度ブックマークを押します。
- ブックマークレットは公式の `/card/` と `/wp-content/card/` 以外は取得せず、このアプリのオリジンからの依頼にしか応えません。
- 解析・間隔制御（400ms）・キャッシュはローカル版と同じ `src/server/dmOfficial.ts` をブラウザ内で使います。

ローカル版で保存したカードを Pages 版へ移すこともできます（データはブラウザごと・サイトごとに保存されるため）。

1. ローカル版（`npm run dev`）の「公式カード検索」でカードを保存する。
2. ローカル版の「カード図鑑 → バックアップ → 書き出す」で、カード・画像・デッキを1つの JSON ファイルに書き出す。
3. Pages 版の「カード図鑑 → バックアップ → 読み込む」でそのファイルを選ぶ（「JSON を選ぶ」でも可）。同じ ID のカード・デッキ・画像は上書きされます。

## 構成

| ディレクトリ | 役割 |
|---|---|
| `src/core/cards` | カード定義の型・検索・JSONインポート・公式カードの変換 |
| `src/core/testing` | テスト専用の架空カードとデッキ（アプリには含めない） |
| `src/core/deck` | デッキ構成ルール（枚数・同名上限・殿堂/プレミアム殿堂/殿堂ペア） |
| `src/core/engine` | ゲームエンジン（UI に依存しない純粋な TypeScript） |
| `src/core/ai` | CPU AI（EASY / NORMAL / HARD） |
| `src/db` | IndexedDB（Dexie）。デッキ・取り込みカード・設定・対戦履歴・中断データ |
| `src/store` | Zustand ストア（画面状態・対戦状態・CPU の自動行動） |
| `src/net` | オンライン対戦（PeerJS）の接続とメッセージ定義 |
| `src/ui` | React の画面とコンポーネント |

### ゲームエンジン

- 入口は `applyAction(state, action, registry)`。新しい状態を返し、違反時は `error` を返す（状態は変わらない）。
- UI とエンジンは `Action` と `GameState` だけでやり取りする。状態は JSON にそのまま保存・復元できる。
- 乱数は状態に持つシード付き乱数なので、同じシード・同じ操作で同じ対戦が再現できる。
- カードの基本情報（`CardDefinition`）と対戦中の個体（`CardInstance`、`iid` で識別）を分離。
- ターン進行の順序は `GameConfig.phaseOrder` で差し替えられる。
- **効果処理キュー**（`state.queue`）：効果・ブロック・シールドブレイク・S・トリガー・バトルをタスクとして順に解決し、プレイヤーの選択が必要になると `state.pending` を立てて中断、`RESPOND` で再開する。
- **イベント**：`CREATURE_SUMMONED` / `CREATURE_DESTROYED` / `ATTACK_DECLARED` などを発行し、誘発能力（出た時・破壊された時・攻撃する時）をキューの先頭に積む。
- **効果処理の3方式**：構造化された効果は自動処理、対象・任意効果は選択式、未対応の効果（`type: 'manual'`）は「要手動処理」とログに出してプレイヤーの手動操作（右クリックメニュー）に任せる。手動操作もすべてログに残る。
- 勝敗：シールド0枚でのダイレクトアタック、山札0枚、投了。

### 対応しているキーワード・効果

- **キーワード**：ブロッカー、S・トリガー、スピードアタッカー、W/T・ブレイカー、パワーアタッカー、スレイヤー、ブロックされない、攻撃できない／プレイヤーを攻撃できない、アンタップしているクリーチャーを攻撃できる、進化、ツインパクト（呪文側の使用・S・トリガー、マナでは両面の文明）。
- **効果（`abilities[].effects`）**：ドロー、山札の上から各ゾーンへ、破壊、バウンス、タップ／アンタップ、マナ送り、手札・墓地・シールド・山札の下への移動、墓地やマナからバトルゾーンに出す、山札の上から見て選ぶ、ランダム手札破壊、シールドブレイク、追加ターン、パワー変更・キーワード付与（ターン終了まで）、ターン終了まで有効な常在効果、条件分岐（if/else）、モード選択、手動処理。対象は「〜まで」「すべて」「相手が選ぶ」を指定できる。
- **誘発タイミング（`when`）**：出た時、破壊された時、離れた時、攻撃する時、ブロックした時、バトルに勝った時、他のクリーチャーが出た時、シールドがブレイクされた時、ターンのはじめ、ターンの終わり、呪文を唱えた時。発動条件（`condition`）と任意効果（`optional`）も書ける。
- **常在効果（`statics`）**：パワー修正（攻撃中のみも可）、キーワード付与、コスト増減（下限付き）、召喚・呪文の禁止。
- **置換効果（`replacements`）**：破壊される時／離れる時に、かわりに手札・マナ・シールド・山札の下へ、とどまる、他のクリーチャーのかわりに破壊される（セイバー）。任意にもできる。

## オンライン対戦（PeerJS）

「対戦開始 → オンライン対戦」で、離れた相手とブラウザ同士で対戦できます。

- 片方が「部屋を作る」と6文字の部屋コードが出ます。もう片方がそのコードで「部屋に入る」と対戦が始まります。
- **ホストがエンジンを動かします**。ゲストは操作（`Action`）を送り、ホストが `applyAction` で判定して、新しい `GameState` を両者に送ります。ホストはプレイヤー0、ゲストはプレイヤー1で、ゲストはプレイヤー1の操作しか送れません。
- **カードの受け渡し**：参加時にゲストが自分のデッキのカード定義を送り、ホストが両デッキの定義をゲストに返します（同じ ID はホストの定義を使う）。画像は、手元にないものだけを相手に頼んで受け取ります。受け取った定義と画像はメモリ上だけで使い、対戦を終えると消えます（IndexedDB には保存しない）。
- **切断**：ホストは部屋を開いたまま再接続を待ちます。ゲストは「再接続」で入り直すと続きから再開します。再戦はホストの「もう一度」、またはゲストの「再戦を申し込む」で始まります。
- 接続の仲介には PeerJS の公開サーバー（0.peerjs.com）を使い、対戦データは P2P で直接流れます。TURN サーバーは使っていないので、携帯回線や一部のルーターでは接続できないことがあります。
- 非公開情報（相手の手札・山札など）は画面で隠しているだけで、ゲストにも状態は全部届きます。友人同士で遊ぶ前提です。
- オンライン対戦は中断保存できません。対戦履歴には「オンライン」として残ります。

## カードデータについて

アプリにはカードを同梱していません。使うカードは次のどちらかで追加します。

- 「公式カード検索」で保存する（下記）。
- 利用条件を確認したデータを「カード図鑑 → JSON を選ぶ」から取り込む（形式は `CardDefinition` の配列）。`abilities` / `keywords` を持たないカードは自動的に「手動処理」扱いになり、エンジンが誤って自動処理することはありません。

```json
[
  {
    "id": "X-001", "name": "カード名", "cost": 3, "civilizations": ["fire"],
    "type": "creature", "races": ["種族"], "power": 3000, "text": "能力テキスト",
    "set": "パック名", "rarity": "C",
    "keywords": { "speedAttacker": true },
    "abilities": [{ "when": "onSummon", "effects": [{ "type": "draw", "count": 1 }] }],
    "support": "full"
  }
]
```

エンジンのテストでは、テスト専用の架空カード（`src/core/testing/fixtureCards.ts`）を使います。アプリからは読み込みません。

## 公式カード検索と保存

ホームの「公式カード検索」から、[デュエル・マスターズ公式カード検索](https://dm.takaratomy.co.jp/card/) の結果と詳細を表示できます。

- 検索と閲覧は、公式サイトからその都度取得して表示します。
- デッキ構築画面の「公式から探す」タブでも検索でき、クリックするとそのままデッキに入ります（未保存のカードはその時に保存）。
- **保存**（詳細画面の「保存してデッキ構築・対戦で使う」、結果ページの「このページのカードを保存」、またはデッキ構築からの追加）したカードだけ、カード情報と画像をこのブラウザの IndexedDB に保存します。デッキ構築・カード図鑑・対戦では保存したデータを使うので、**公式サーバーへはアクセスしません**。保存済みのカードは再取得しません。
- 保存したカードのキーワード能力（ブロッカー、S・トリガー、W/T/Q・ブレイカー、スピードアタッカー、スレイヤー、パワーアタッカー、攻撃制限など）は自動処理になります。それ以外の能力は「手動処理」扱いで、エンジンが勝手に処理することはありません。ツインパクトは呪文側も使えます。
- 保存したカードと画像は、カード図鑑の「保存した公式カード」から一括削除できます。ファイルとしては保存しないので、リポジトリには入りません。
- ブラウザから公式サイトへは CORS で直接アクセスできないため、Vite のサーバー（`npm run dev` / `npm run preview`）が中継します（本体は `src/server/dmApi.ts`）。Pages 版では公式サイトのタブがブックマークレットで中継します（上記）。中継は公式のカード画像パス以外を取りに行きません。
- 公式サーバーへのリクエストは1本ずつ間隔（400ms）を空けて送り、同じ検索・詳細は10分間メモリにキャッシュします。
- 公式サイトの HTML 構造に依存しているため、サイトが変わると取得できなくなる場合があります（解析は `src/server/dmOfficial.ts`、変換は `src/core/cards/officialConvert.ts`）。
- 個人利用の範囲で使ってください。

## プロキシPDF（A4印刷）

デッキ構築画面の「プロキシPDF（A4）」から、デッキの全カードを実寸（63×88mm）で A4 縦に 3×3 枚ずつ並べた PDF を作ってダウンロードできます。

- 画像はブラウザに保存済みのもの（公式カードを保存した時の画像）を使います。画像がないカードは、名前・コスト・文明・種族・テキスト・パワーを描いた文字だけのプロキシになります。
- カードの間隔（0/1/2mm）、倍率（95〜101%）、裁断用のトンボ（並びの外側の余白にだけ引く線）を選べます。
- 印刷時は「実際のサイズ（100%）」を選び、「用紙に合わせる」をオフにしてください。
- PDF は外部ライブラリを使わずに組み立てています（`src/core/print/proxyPdf.ts`、画像の描画は `src/ui/proxyPrint.ts`）。

## テキストからデッキを作る

AI などで作ったデッキリストを貼り付けて、そのままデッキにできます（デッキ一覧の「テキストから作成」、またはデッキ構築の「テキストから取り込み」）。

- 読める形：Markdown の表、画面の表をコピーしたタブ区切り、`《カード名》×4`、`4 カード名`、`カード名 4枚` など。見出し・合計の行は無視します。
- カード名は、保存済みのカード → 公式カード検索の順に探します（`/dm-api/resolve`）。空白・中黒・全角半角の違いは無視し、ツインパクトは片面の名前でも見つけます。書き間違いは似た名前を候補に出し、「確認してください」と表示します。
- 候補はプルダウンで選び直せます。公式のカードは反映した時にブラウザへ保存します。
- 読み取り処理は `src/core/deck/deckText.ts`。
